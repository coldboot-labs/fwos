# Installer requires disk selection and wipe approval; identity stays Bootstrap

The Installer is Anaconda text: it writes the Host disk layout onto one non-removable disk the operator has chosen and explicitly approved, then ejects the ISO if it can and reboots into the Host image. One non-removable disk still names that disk, explains that it will be fully erased, and waits for a typed `yes`. More than one: the operator picks which disk, then the same approval. If the disk already has partitions, list them when we can and say they will be overwritten with the Host disk layout. Decline (anything other than `yes`) writes nothing. Removable media, loop, ram, and optical devices are not targets. The chosen disk is always wiped; there is no keep-`/var` reinstall, custom partitioning, dual-boot, graphical Installer, or Installer-as-updater. Identity (admin, hostname) remains the Bootstrap UI after First install, so the Disk image and the Installer still boot the same unpublished-identity Host image.

This supersedes ADR-0021 (unattended when there is exactly one writable disk). Considered: collecting hostname/admin in the Installer; Anaconda GUI or a custom ISO wizard. Rejected — identity would split the two First-install paths; a GUI is a Fedora installer for two TUI questions.
